# One-package Nimbalyst deployment 4.2

For prerequisites, shell-specific installation steps, and the portable operator path, start with [Getting started locally](GETTING_STARTED.md). Repository distribution is covered in [Publishing](PUBLISHING.md). The runtime-specific checklist below still needs live verification in each user's environment.

1. Fresh folder; open root with START_HERE/AGENTS. Do not layer previous ZIP/overlay/signals supplement. Existing real data needs backup/reviewed migration.
2. Settings > Project > Trackers: 4 types; 5 DEMO cards (initiative+child, task, feature, backlog). Schema drift→review then Resync from files. Full-document cards top-level title/status; trackerStatus={type}. Change DEMO task inbox→ready and inspect file, then revert. Native child-tree UI not claimed; iteration_of is canonical relation. Until a UI-created card is live-tested, create cards from templates/: tracker files define only UI fields, and check_package/build_indices reject a card without id+entity_type.
3. Provider setup: verify actual Claude/Codex versions/discovery/models/permissions. Starter Claude MCP denied; Claude Bash limited to the coordinator scoped shell (allowlist in .claude/settings.json + hook tools/shell_guard.py), restart the session after settings change. Local Write/Edit depends on actual permission mode. Codex parent read-only and shell off; coordinator there returns payload+command to operator. Owner enables reviewed scoped local mode if needed, not bypass. Reviewers read-only tools, OS isolation separately verified.
4. Signals table already inside signals/. No second spreadsheet, DB or tracker item. Empty on purpose. Initial capture through approved local tool or coordinator candidate reviewed by operator. No bulk fake records. tools/signals.py hash; list (filter by --related/--status)/get/capture/update use expected hash and coordinator writer; export writes the safe derivative. If shell denied, trusted operator runs tools; never bypass.
5. Trusted local commands (Python3.11+, dependencies approved). Venv must be ~/.venvs/pm-os: outside the repo because check_package scans it, and the scoped shell allows only this interpreter.
   python3 -m venv ~/.venvs/pm-os; source ~/.venvs/pm-os/bin/activate; pip install -r requirements.txt
   python tools/build_adapters.py
   python tools/build_indices.py
   python tools/check_package.py
   PMOS_RELEASE_CHECK=1 python -m unittest discover -s tests -v
   python tools/build_manifest.py
   python tools/verify_manifest.py
   PMOS_RELEASE_CHECK=1 adds 3 tests of the untouched release state (only DEMO cards, unconfigured profiles, empty CSV); drop it after setup, plain unittest stays the regression suite. Keep DEMO cards: tests use them as fixtures, search excludes them by default. Operator reruns build_manifest after reviewed changes; verify_manifest proves integrity against that baseline only.
6. Start either bootstrap prompt and follow [first-launch setup](procedures/setup.md): analyse user input and saved choices, scan relevant existing files, prefill supported context with provenance, then use one interactive intake for gaps/conflicts. Apply confirmed profile/preferences updates within actual rights and run a real low-risk pilot. Missing Python/environment/dependencies require the operator steps in [Getting started](GETTING_STARTED.md) and the preflight in [tool requirements](tools/README.md). Diffs/Owner gate decisions/keeper knowledge remain required. DEMO is not real context; a starter's empty profiles are onboarding inputs, not a failed pilot.
7. Local loops onboarding is defined in [profile/loops.md](profile/loops.md): three disabled Nimbalyst automation definitions (daily inbox twice, weekly focus/backlog) and a manual BRD loop. Verify runtime discovery, timezone/DST, sleep/missed-run and output behavior; run a real manual pilot per workflow, then record Owner review before the operator enables schedules. Definitions do not prove live execution. Initial scheduled scope is drafts only. External automation later requires broker/auth/outbox/reconciliation/MCP/DLP/scheduler/models-cost eval/restore drill. Changing a policy boolean does not implement these.
CSV native table UI not guaranteed; use local file/tool. Spreadsheet export is separate sanitized derivative under artifacts/, not new canon.
