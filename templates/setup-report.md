# setup-report
## Required content
Owner/product/value-map/team/tone/stack; inventory IDs/paths/hashes/ACL; actual runtime/provider/models/agents/skills/4 tracker types/top-level UI smoke; signal header+source rights+writer mode; actual executed vs pending readiness.
## First-launch evidence
- User input and prior explicit choices reused; bounded scan scope/method/paths/hashes, exclusions, coverage gaps and stop reason. DEMO/reference are not real context.
- Prefilled values -> source/locator/hash -> user statement/fact/assumption/unknown -> confidence -> verification. Record conflicts and the user's resolution; do not turn an inferred capability into verified access.
- Remaining intake gaps, confirmed profile/preferences diff and pending read-only/operator handoffs. Supported setup values and completed pilots are separate outcomes.
- Python executable/version, external venv path, dependency versions/import checks; missing environment as runtime_setup_pending with exact operator steps. Record actual commands/results and unrun checks.
- Native tracker discovery: canonical cards versus master-template items; schema/UI creation checks and remaining gaps. Local package counts alone do not establish live UI correctness.
## Loops onboarding
- Settings path and hash; chosen workflows; actual schedule files/hashes/times/days/enabled; timezone assumption vs operator-verified scheduler timezone/DST/sleep behavior.
- Inbox allowlist/ACL; BRD document/source refs/acceptance/independent reviewer; missing inputs remain explicit.
- Per-workflow pilot report/session/inputs+hashes/result and Owner review; inbox repeated-input result. Distinguish blocked/no-data from a passed real pilot.
- Owner activation quote/ref and actual enabled state after operator action. No automatic enabling or reset of existing preferences. Draft-only scope and pending live checks.
## Signals
Relevant SIG IDs in signal_refs; verify source evidence, never copy CSV as a second registry.
